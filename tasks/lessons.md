# Lessons

再発可能な問題について、問題・原因・次回の予防または確認方法を簡潔に記録する。

- 問題: Functions配下の管理用認証ファイルがデプロイ用アーカイブへ含まれ得る設定だった。原因: Firebase CLIのソース梱包はGitの除外指定を自動適用せず、functions.ignoreを参照する。予防: firebase.jsonのfunctions.ignoreへ認証ファイルを明示し、CLIと同じファイル列挙処理で梱包対象から除外されたことを公開前に確認する。

- 問題: Functionsの通知テストでfirebase-adminのモックが適用されず、未初期化アプリのエラーになった。原因: アプリ直下とfunctions配下の同名パッケージが別モジュールとして解決された。予防: Functionsが実際に解決する依存パッケージをモックし、送信・Firestoreアクセスが偽物に置き換わったことを確認する。テストを通すために本番認証を初期化しない。

- 問題: 過去チャットの追加読み込みで新着表示が出て、最新投稿が自分の場合に最下部へ強制移動した。原因: 総件数の増加を新着とみなし、追加された投稿ではなく既存の末尾投稿で送信者を判定していた。予防: 新しい末尾IDと過去履歴の追加を区別し、履歴追加前後で閲覧中メッセージの画面内位置を維持する。過去50件追加・最新50件の入れ替わり・新着との同時追加を回帰テストする。

- 問題: 非表示の検索モーダルや環境外のElectron機能がFirestore購読を開始し、少人数運用でも無料枠に迫った。原因: 表示・副作用側だけを条件分岐し、データ取得hookへのユーザー引数を常時渡していた。予防: 購読開始条件をhookの入口で制御し、非表示・対象外環境では`null`または`subscribe: false`を渡す。
- 問題: 予定画面と通知機能が過去分を含む全予定を重複して`onSnapshot`した。原因: 共通hookの既定クエリに期間・用途フィルタがなかった。予防: 通常画面は表示期間、通知は`notification.enabled`、全件検索は明示操作時だけに限定し、本番件数で初回読み取り量を見積もる。
- 問題: 定期Functionsが取得後に状態を絞り込み、不要な文書を毎分読んだ。原因: Firestoreクエリではなくアプリ側でフィルタしていた。予防: 状態・時刻条件をクエリに含め、必要な複合インデックスをFunctionsより先に反映・有効化する。
- 問題: ルーム本体だけの削除では、メッセージ、既読状態、通知設定、Storageファイルが残る。原因: クライアント側の削除処理が関連データのライフサイクルを統括していなかった。予防: 完全削除は認証付きFunctionに集約し、Rulesで削除中の新規書き込みを止め、関連データを消してからルーム本体を最後に削除する。
- 問題: 作成者フィールドがない既存ルームへ作成者権限を追加すると、旧クライアントと既存データで権限判定できない。原因: スキーマ追加だけでは段階反映中の欠損を補えない。予防: 新規書き込み、旧クライアント向け作成トリガー、ドライラン可能な既存データ移行、`members[0]`の互換フォールバックをセットで実装する。
- 問題: 過去の環境情報だけを根拠にRulesテストを省略すると、現在実行可能でも未検証になる。原因: Javaの有無が環境更新で変わることを再確認していなかった。予防: ルール変更時は毎回`java -version`を確認し、利用可能なら`npm run test:rules`を実行する。
- 問題: 添付ファイルの選択イベントから直接アップロードすると、送信前の確認や取消ができず、誤送信につながる。原因: ファイル選択とメッセージ送信を同じ操作として実装していた。予防: 選択・ドロップ時はローカルの保留一覧だけを更新し、StorageとFirestoreへの書き込みは送信ボタンの処理に限定する。
- 問題: 新規1対1チャットの選択を押しても画面が変わらなかった。原因: メンバーだけ読み取り可能な`chatRooms`で、作成前の存在しない固定ID文書を`getDoc`し、権限エラーを未処理のまま終了していた。予防: 保護コレクションの固定ID作成は事前readに依存せずcreateを先に試し、既存競合だけメンバー確認へフォールバックし、非同期操作中と失敗をUIへ表示する。
- 問題: `retry: true`のFirestoreトリガーで未読数を単純に`increment(1)`すると、同じイベントの再配信で二重加算される。原因: 再試行ポリシーと書き込みの冪等性を別々に変更していた。予防: 再試行を有効にするトリガーは、イベント固有の適用済み記録と本体更新を同一トランザクションで行い、Firebaseが`--force`を求めた場合は対象関数ごとに冪等性を確認する。
- 問題: Electronかどうかだけでデスクトップ導線を決めると、ウィンドウ縮小時もチャット一覧ルートが予定表へ戻される。原因: 実行環境と表示幅の判定を分けていなかった。予防: Electronでも縮小時はモバイル導線を使い、自動遷移と利用者が明示的に選び直した遷移を別の状態で扱う。
- 問題: ルーム未選択の`/chat`を追加した際、ルームIDがないとメッセージ購読hookの`loading`が初期値のままになり、空状態が永続的な「読み込み中」になる。原因: 購読しない状態と購読中の状態を同じloading判定で扱った。予防: 任意IDを受ける画面は`IDがある && loading`で待機し、IDなしの空状態を先に描画できることをテストまたは実画面で確認する。
- 問題: ルーム情報に多数のメンバーがいると、メンバーカードの内容が後続カードへはみ出して重なった。原因: 縦方向のFlexコンテナ内で、件数に応じて高さが変わるカードが既定の縮小対象になっていた。予防: 可変件数を含むカードは`flex-shrink: 0`で内容高を保ち、親ペイン側をスクロールさせて大量件数でも重ならないことを確認する。
- 問題: Electronを狭幅にした際、スマホWebへ切り替わるか、641〜1023pxで3カラム部品が装飾なしに表示された。原因: 「狭幅ならチャット一覧」という遷移要件をスマホ用の`640px`境界に合わせた一方、3カラムCSSは`1024px`以上でしか有効にならず、中間幅に表示契約がなかった。予防: Electronコンパクト表示は3カラム境界直前の`1023px`まで担当させ、スマホWebのHome表示とはルート・判定とも分離して境界値をテストする。
- 問題: コンパクトなチャット一覧を実装しても、Electron本体の`minWidth`が580pxのままで、それ以上ウィンドウを縮められなかった。原因: レンダラー側のレスポンシブ対応とネイティブウィンドウ制約を別々に扱っていた。予防: 狭幅UIを追加・変更するときは、Electronの最小サイズと主要ボタンの可読性をセットで確認し、最小幅を回帰テストで固定する。
- 問題: 左ペインを最大幅にしてからウィンドウを縮小・復元すると、境界が最小側のまま戻らなかった。原因: 画面へ収めるため一時的にクランプした表示幅で、ユーザーが保存した希望幅の参照まで上書きしていた。また予定表は同じ幅設定とリサイズ操作を共有していなかった。予防: 希望幅と現在の表示幅を別管理し、ウィンドウリサイズでは希望幅を変更しない。共通hookと保存キーをチャット・予定表の両方で使用する。
- 問題: 埋め込みチャットの閉じる処理をインライン関数で渡すと、親画面の再描画ごとにルーム購読が解除・再作成され、Firestoreの読み取りが増える。原因: `onSnapshot`を持つeffectの依存配列へ、毎回新しいコールバック参照が入る。予防: 購読を閉じるコールバックは親で`useCallback`により固定し、表示操作だけの再描画で再購読されないことを確認する。
- 問題: 埋め込みチャットに戻るボタンを実装しても、デスクトップ幅では表示されなかった。原因: デスクトップ用の高詳細度セレクターが`display: none`を指定し、後段の埋め込み用スタイルが詳細度で負けていた。予防: レスポンシブCSSで既存要素を再表示するときは非表示ルール以上の詳細度で明示し、境界幅を含む表示回帰テストを追加する。
- 問題: Electronコンパクト表示から予定表・工程管理へ通常遷移すると、予定表は狭幅ガードで即時に戻り、工程管理はPCレイアウトが崩れた。原因: 遷移ボタンと各画面の表示幅契約が統一されていなかった。予防: 横幅を必要とする画面はElectron側で作業幅を確保し、レンダラーが幅変更を確認してから遷移する共通導線にする。
- 問題: Cloud Functions の Node.js 20 ランタイムは 2026-10-30 の廃止後に再デプロイできなくなる。原因: `firebase.json` の Functions ランタイムが廃止予定の `nodejs20` に固定されている。予防: 廃止日より前にサポート対象ランタイムで依存関係・エミュレータ統合テスト・本番Functionsを検証し、段階的に移行する。
- 問題: Windows上のElectronビルドで、展開直後の`win-unpacked.tmp`を`win-unpacked`へ変更する処理が`EPERM`になった。原因: electron-builderの標準展開処理中に一時フォルダのハンドル解放が間に合わない場合がある。予防: 失敗成果物を検証済みの隔離先へ移動し、`node_modules/electron/dist`を`electronDist`として明示して再ビルドする。公開前に通常の成果物検証を必ず通す。
- 問題: Firebaseの統合テストを連続実行すると、直前のPub/Subエミュレータがポート8085を保持して次のテストを開始できないことがある。原因: テスト終了後もJavaプロセスの停止が完了していない場合がある。予防: 再試行前にポート所有者を確認し、今回起動したPub/SubエミュレータのJavaプロセスだけを停止してから実行する。
- 問題: Cloud Billingの停止を解消してStorageが戻っても、通知Functionsは「利用可能なインスタンスなし」のまま復旧しなかった。原因: 請求停止中に第2世代Functionsの実行基盤も停止し、請求再開だけでは新しい実行インスタンスが立ち上がらなかった。予防: 請求復旧後はStorageだけでなく通知・定期Functionsのログを確認し、必要なら対象関数だけを再デプロイしてACTIVE・起動プローブ・実行成功まで確認する。
- 問題: GitHub Releaseの`v1.3.1`タグが実際に公開したバックエンドソースを指しておらず、障害復旧元として使えなかった。原因: リリース成果物とGitタグのコミット内容が一致していなかった。予防: Electronリリース時はタグ名とアセットだけでなくタグ先コミットのバージョン・Functions export一覧も照合し、復旧可能なソースを残す。
- 問題: リポジトリを非公開にすると、インストール済みの Electron が更新を受け取れなくなる。原因: 更新先はビルド時にアプリへ書き込まれ、v1.3.4 以前は GitHub Releases を見ている。予防: 新しい更新先を指す版を、旧クライアントがまだ届く GitHub Release に1回出し、全端末のバージョンがそれ以上だと確認してから非公開にする。更新ファイルは PWA の `dist` に混ぜず、`docs/desktop-updates.md` の専用サイトへ出す。
- 問題: `.gitignore` に書いた `.env` がリポジトリに残っているように見える。原因: 一度追跡されたファイルは gitignore では外れない。予防: 秘密の有無を見るときは `git ls-files` で追跡されているかを確認し、値はログ・手順・コードに出さない。
- 問題: 吹き出しの一部をドラッグするとメニューが開き、名前や入力欄まで選択が青くなる。原因: ポインタを離すたびにメニューを開き、その再描画で本文のDOMが作り直され、選択を止める指定も本文以外に無かった。予防: マウスの移動ではメニューを開かず、選択の始点が本文ならその本文へ戻す。メニューの開閉では本文を再描画しない。タッチの長押しだけブラウザの選択を消してメニューを出す。
- 問題: 添付の選択欄だけ形式を絞ると、ドロップでは実行形式が通り、gz は Storage の許可リストで落ちる。原因: 入口と保存ルールで別の許可リストを使っていた。予防: 実行形式の拡張子拒否を、選択・ドロップ・貼り付けと Storage のファイル名の両方に置く。exe の拒否と gz の許可をルールテストする。
- 問題: ウェブページのタイトルを表示のたびに取りに行くと、無料枠の通信を超えやすい。原因: 閲覧回数だけ取得が走る。予防: 送信時に1回だけ取得してメッセージへ保存する。社内アドレスと転送先は拒否し、失敗時はリンクだけを残す。過去のメッセージは取り直さない。
- 問題: 未公開の版番号を繰り上げると、手順書だけが「次の版は Firebase だけで足りる」と残る。原因: インストーラー名と「GitHub に1回出す橋渡し版」の番号が、package.json とは別に文書へ書いてある。予防: 版番号を変えたら package.json、package-lock のルート、更新ノート、手順、テストのファイル名を同時に直し、橋渡し版の次の番号だけを Firebase 専用にする。依存パッケージの同番号は変えない。
