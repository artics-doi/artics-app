# v1.3.6 の本番反映

v1.3.6 は公開済みです。次の版は [v1.3.7-backend.md](v1.3.7-backend.md) です。v1.3.7 以降、更新ノートはアプリ同梱が正本で、この文書の「更新ノートを保存」は使いません。

この手順は、アプリを公開する人が本番へ出すとき用です。リポジトリに入っているだけでは、本番の関数・ルール・Hosting はまだ変わっていません。デスクトップのインストーラー手順は [desktop-updates.md](desktop-updates.md) です。

プロジェクト ID は `company-chat-a9cf0` です。Cloud Functions を既に使っているため Blaze プランです。Spark のままでは関数を追加できません。

## 必要な権限

次を1人のアカウントで持つのが確実です。

- Firebase のオーナー、または `roles/firebase.admin`（Firebase Admin）
- 更新専用サイトの作成: Firebase Hosting 管理者（`firebasehosting.sites.create` と Hosting のデプロイ）
- ルール: Firebase Rules 管理者（Firestore ルールと Storage ルール）
- 関数: Cloud Functions 管理者、Cloud Build、Artifact Registry への書き込み、関数の実行サービスアカウントに対する Service Account User。第2世代関数のデプロイでまとめて求められます

`npx firebase login` で、このプロジェクトに対して上記ができる Google アカウントを使います。

## 変更の有無

| 対象 | この版 |
|---|---|
| Firestore ルール | 変える。`linkPreviews` をクライアントから読めなくする |
| Firestore インデックス | 変えない。`firestore:indexes` は出さない |
| Storage ルール | 変える。25MB 以内で、実行形式の拡張子を拒否する |
| Functions | `fetchLinkPreview` だけを追加する。既存の export 名は変えていない |
| Web 版 Hosting | 出す。PWA も選択コピー、リンク表示、添付の変更を受け取る |
| Realtime Database | 変えない |

インデックスは `firestore.indexes.json` を変えていません。まとめて `firebase deploy` しないでください。

## 出す順番

1. この PR は `refactor/agent-friendly-202606` に取り込みます。`main` は v1.0.2 の古い線です。取り込んだコミットを checkout し、`package.json` の `version` が `1.3.6` であることを確認します。

2. 更新専用サイトを、Windows のインストーラーを作る前に空で作ります。ファイルはまだ上がりません。

```bash
npx firebase login
npx firebase hosting:sites:create company-chat-a9cf0-updates --project company-chat-a9cf0
```

3. ルールを出します。これを先にしないと、gz などの新しい添付は Storage で拒否され、ドロップ経由の実行形式も閉じません。Firestore ルールも同じコマンドに含めます。インデックスは含めません。

```bash
npx firebase deploy --only firestore:rules,storage --project company-chat-a9cf0
```

4. プレビュー用の関数だけを出します。リージョンは `asia-northeast1` です。クライアントも同じ地域を呼びます。

```bash
npx firebase deploy --only functions:fetchLinkPreview --project company-chat-a9cf0
```

`firebase deploy --only functions` のように関数をまとめて出す場合も、`functions/src/index.ts` の export 名を消していないことを先に確認してください。export 名がデプロイされる関数名です。

5. Web 版を出します。`npm run build` は PWA 用です。`npm run build:electron` のあとの `dist/` は出さないでください。Service Worker が欠けます。この Hosting は `firebase.json` の既定サイトで、更新専用サイトとは別です。

```bash
npm ci
npm run build
npx firebase deploy --only hosting --project company-chat-a9cf0
```

6. Windows でインストーラーを作り、更新ファイルを Firebase の更新専用サイトへ先に置き、そのあと GitHub Release `v1.3.6` を作ります。コマンドは [desktop-updates.md](desktop-updates.md) の「v1.3.6 を出す」です。Linux でのクロスビルドは使いません。

7. Web 版とデスクトップ版の両方が取れるようになってから、管理者が更新ノートを保存します。`docs/release-notes/v1.3.6.draft.txt` を、既存の `settings/releaseNotes` の本文の先頭に貼ります。日付は 2026/10/22 で確定です。

## 動作の要点

- 利用者はログインしていないとプレビュー関数を呼べません。
- 取得は送信時の1回だけです。結果のタイトル、説明、サイト名は、そのメッセージに保存します。
- 同じ URL は `linkPreviews` に7日覚えます。このコレクションはクライアントから読めません。
- https 以外、社内・ローカル・メタデータアドレス、そこへの転送先は取りません。
- HTMLは保存せず、文字だけを保存します。1メッセージにつき先頭の1件だけです。過去のメッセージは取り直しません。失敗したときはリンクだけを表示します。画像は取りません。
- 添付は 25MB 以内なら送れます。ただし `.exe` `.bat` `.cmd` `.com` `.scr` `.msi` `.dll` `.js` `.vbs` `.ps1` `.hta` `.lnk` と、その抜け道になるスクリプト形式は送れません。zip にまとめれば送れます。
