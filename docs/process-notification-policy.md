# 工程管理の通知先（v1.3.4）

- 通知のマスターON/OFFは廃止。各メンバーの「通知設定」で担当タスクの受信アクションを選択する。
- 対象はイベント発生時のタスクの `assigneeIds` に含まれる工程管理メンバー。Auth UIDではなく `processMembers` の文書IDで照合し、`linkedUserId` へ配信する。
- `isTaskProgressManager: true` の登録メンバーは、担当・個別設定にかかわらず全プロジェクトの全6アクションを受信する。複数人の追加・解除に対応し、メンバー削除時には管理者資格もなくなる。
- アクションは新タスク、未着手、進行中、完了、保留、完了承認。並べ替え・日付・担当者だけの編集・アーカイブは通知しない。
- 完了承認は完了列の未チェックからチェックへの変化。チェック解除では通知しない。
- 担当未設定の場合は管理者のみ。担当兼管理者や同一UIDの重複レコードでも通知は1件。
- 既存 `notification.events` は維持し、旧 `enabled` は無視する。設定がない場合は全6種類が既定値、空配列は担当者としての受信なし。旧OFFの担当者も今後は選択済みアクションを受信する。
- 管理者の既定値はfalse。旧データの書き換えや自動管理者登録はしない。登録アカウントに紐付いていないメンバーへは通知しない。
- 設定は従来どおりアクティブなログインユーザー全員が編集可能。管理者フラグは通知対象の指定であり、アプリの認証・削除等の権限を増やさない。
- 受信箱はイベント時の担当IDと `recipientPolicyVersion: 2` を保持。Push直前にも担当・管理者・アクション設定を確認し、解除済みや旧仕様の保留通知は配信しない。
- 端末全体の通知設定やOSの通知許可は従来どおり優先される。

## 本番反映時の注意

UIとFunctionsの新しい通知先判定をセットで反映する。旧クライアントのON/OFFは新サーバーでは意味を持たないため、公開時はアプリ更新を案内する。最新のクライアントは設定保存時に旧enabledを除去する。Firestoreルールや本番データの移行は不要。
