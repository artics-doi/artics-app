# v1.3.5 の Functions と Storage ルール

この手順は、アプリを公開する人が本番へ出すとき用です。この変更を入れただけでは、本番の関数とルールはまだ変わっていません。

## 先に必要なこと

- プロジェクト `company-chat-a9cf0` は、Cloud Functions を使っているため Blaze プランです。Spark のままでは関数を追加できません。
- URLプレビューの関数は `asia-northeast1` です。クライアントも同じ地域を呼びます。
- 過去のメッセージは取り直しません。新しく送ったメッセージだけ、タイトルと説明が付きます。
- 画像は取りません。失敗したときは、これまで通りリンクだけを表示します。

## 出す順番

1. ルールを出す。これを先にしないと、gz などの新しい添付はクライアントが許可しても Storage で拒否されます。

```bash
firebase deploy --only firestore:rules,storage --project company-chat-a9cf0
```

2. プレビュー用の関数だけを出す。既存の関数名は変えていません。

```bash
firebase deploy --only functions:fetchLinkPreview --project company-chat-a9cf0
```

3. そのあとで、この版のアプリを利用者へ渡します。関数がまだ無い間にアプリだけ先へ出しても、メッセージ自体はリンクだけとして送れます。プレビューのカードは付きません。

`firebase deploy --only functions` のように関数をまとめて出す場合も、`functions/src/index.ts` の export 名を消していないことを先に確認してください。export 名がデプロイされる関数名です。

## 動作の要点

- 利用者はログインしていないと関数を呼べません。
- 取得は送信時の1回だけです。結果のタイトル、説明、サイト名は、そのメッセージに保存します。
- 同じ URL は `linkPreviews` に7日覚えます。このコレクションはクライアントから読めません。
- https 以外、社内・ローカル・メタデータアドレス、そこへの転送先は取りません。
- HTMLは保存せず、文字だけを保存します。1メッセージにつき先頭の1件だけです。
- 添付は 25MB 以内なら送れます。ただし `.exe` `.bat` `.cmd` `.com` `.scr` `.msi` `.dll` `.js` `.vbs` `.ps1` `.hta` `.lnk` と、その抜け道になるスクリプト形式は送れません。zip にまとめれば送れます。
